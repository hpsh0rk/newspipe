|---|---|---|---|
| 采集内核 | slot/poll 调度、四轴配置（fetch/filter/enrich/deliver） | 定时把信源变成条目 | 自动化 |
| AI 加工 | 中文标题/摘要/翻译、回执缓存、预算熔断、降级 | 英文源变中文卡 | 自动化 |
| 投递 | 卡片实体 + 原地翻页、元素预算、去重台账、顺延队列 | 内容到飞书 | 用户（IM 里） |
| 交互闭环 | 卡片点击 → 状态机、⭐收藏 → 待入库队列（人环）、hook 扩展按钮 | 点击改状态、收藏等人确认 | 用户 + 宿主 Agent |
| 观测 | 心跳（状态码+标签+语气+超期）、事件流（6 类）、趋势 14 天、诊断抽屉 | 回答「为什么是这样」 | 维护者 |

一级导航 4 Tab 平铺；二级 = 页内 `<h2>` 段落；批次详情挂在条目 Tab 下。

### 1.3 功能清单 vs 使用频率（依据：使用场景推断 + 维护者可确认）

- **高频（每天数次）**：看今天发了什么/是否正常；⭐ 确认入库；点开条目读内容。
- **中频（每周）**：手动跑一轮；筛选回看条目；RSS 搜索订阅。
- **低频（每月或更少）**：改源四轴配置；增删源；趋势/诊断深挖；事件消费。
- **错位**：高频的「看」被低频的「管」淹没——运维页 46 个按钮无主次；事件批量 ack 本是宿主 Agent 经 CLI 的职责（AGENTS §3），却以 30 按钮墙占住运维页。

### 1.4 繁杂症状

1. **同类功能分散**：同一「信源」实体在 3 个页面以 3 种列结构渲染（驾驶舱运行态 8 列 / 运维动作 9 列 / 配置编辑 6 列）。
2. **页面重复**：`as_html()` 同一函数渲染驾驶舱与运维 → 趋势表、信源表、诊断抽屉、今日批次两页各一份，约 90% 重叠。
3. **单页密度超标**：驾驶舱 6 大块无主次；运维 7 段 46 按钮 74 行。
4. **路径冗长**：新增信源 = 页中搜索 → 跳 `#new` 锚点到页底表单，动线两头跳。
5. **实现细节泄漏**：footer / write_note 反复解释「写路径只有一条」「白名单在代码里」——架构注释当产品文案，每页重复。

## 4. 简化方案（保留 / 合并 / 折叠 / 下线）

- **保留**（动线不变）：运维顶部「跑一轮」工具条；条目页筛选 + 批次详情；配置页演练/并发保护/四轴结构；`/view` 契约与全部路由。
- **合并**：
  - 驾驶舱与运维拆开渲染：驾驶舱 = **看**（只读总览），运维 = **做**（动作）；重复的趋势/今日批次/诊断抽屉只留一处。
  - 信源实体单点化：完整运行态表 + 行内动作收敛到运维页；驾驶舱只留「源名 + 心跳 pill + 一句话原因」。
  - RSS 搜索 + 新增表单 → 「添加信源」一个区块（搜索命中即预填表单），置于配置页首。
- **折叠**（渐进披露，保留可发现性）：
  - 驾驶舱：14 天趋势、今日批次 → `<details>`；KPI 7→4（今日条目 / 已发卡 / AI 降级(非 0 才显示) / ⭐待确认(链接运维)）。
  - 运维：未消费事件、顺延明细 → 折叠；每页页首元信息行 → 页脚小字。
- **下线**：footer 架构注释（移入 README/AGENTS）；运维页事件 ack 按钮墙（归宿主/CLI）；「今日点击」KPI（证据：无消费方，且计数来源 actions.log 行数语义弱）。

**兼容承诺**：`TABS` id 与 URL 不变；`/view` v1 字段只增不删；`/api/actions/*` 白名单与表单字段名不变。全部改动是**渲染层减法**（只动 `view.py` 的 `*_html()` 与 `style.py`），分 4 个独立可回退提交（每 Tab 一个），无大爆炸改版。
